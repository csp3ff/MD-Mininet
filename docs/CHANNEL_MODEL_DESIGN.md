# 信道到仿真链路参数的建模设计

更新日期：2026-10-05。本文确定网络层仿真的模型边界、参数归属和计算路径。它是物理建模设计文档；版本 2 的直接链路结果时间片及下发代码已另行加入，见 [链路时间片说明](CHANNEL_TIMELINE.md)，但尚未运行验证。本文所述节点/环境参数到无线链路结果的模型仍未实现。

## 1. 模型目标与术语

每条**预先声明的候选链路**按方向、按仿真时间生成：

```text
LinkState(link_id, direction, sim_time_ms) =
  {available, bandwidth_mbps, propagation_delay_ms,
   residual_packet_loss_pct?, jitter_ms?}
```

`bandwidth_mbps` 对应将来要配置的**网络接口目标整形速率**，是链路服务能力的网络层近似值；它既不是无线频谱宽度（Hz），也不是 PHY 标称速率或应用实测吞吐。`propagation_delay_ms` 严格表示该方向的信号传播时间；当前源码的 `ChannelState.delay_ms` 保持此语义。`residual_packet_loss_pct` 只表示链路层重传等机制之后仍未交付的报文损失，未知时为 `None`，不能把原始误块率直接填进去。

由业务负载决定的排队时间和实际端到端吞吐不属于 `LinkState` 的预设常数。节点角色（Mininet Host/OVS Switch）与物理实体类型（终端、基站、无人机、卫星）分别记录：一个 OVS 节点可以代表带有无线接口的基站，但 OVS 虚拟端口参数不是基站射频参数。

## 2. 参数归属与对链路的作用

所有数值保留单位、设备型号、数据来源、采集时间、适用条件。节点档案保存设备能力，节点状态保存当前配置与姿态；障碍、天气和其他发射者保存在共享环境。缺少关键输入时输出“未建模”或报错，不用虚构常数补齐。

| 参数 | 归属 | 直接影响 | 首版优先级 |
| --- | --- | --- | --- |
| 三维位置、天线高度 | 节点状态；卫星位置来自轨道/星历 | 路径长度与传播时延、仰角、路径损耗、可见性 | 必需 |
| 速度、航向、姿态、天线指向 | 节点状态 | 后续位置、天线方向增益、多普勒；速度本身不令电磁波变慢 | 移动场景必需 |
| 载频、工作频段、信道宽度、发射功率 | 无线电档案与当前配置 | 路径损耗、噪声、SINR、可选 MCS 与速率 | 定量速率必需 |
| 发射/接收天线方向图、增益、馈线损耗 | 设备档案与姿态 | 两端方向上的接收功率；未测得时使用有标注的简化模型 | 定量速率必需 |
| 接收机噪声系数、可支持 MCS、灵敏度 | 接收端设备档案 | SINR、可解码状态、速率上限 | 定量速率必需 |
| 射频链数、设备速率上限、网口速率 | 设备档案 | 速率硬上限；不能当成当前链路可用速率 | 必需 |
| 分配频谱/时隙比例、占空比、调度规则 | 共享资源与协议配置 | 实际可获得的服务速率、接入等待 | 定量速率必需 |
| 建筑/车辆遮挡、地形、LOS 状态 | 共享环境，由几何或指定模型确定 | 路径损耗、可用性、速率与可能的残余损失 | 场景相关 |
| 同频发射者及功率、噪声环境 | 共享环境 | 干扰与 SINR；共享频谱的链路不能各自独立抽样 | 多链路场景必需 |
| 雨、云、气体等天气参数 | 共享环境 | 适用频段的附加衰减，进而影响速率/可用性 | 卫星等场景按需 |

不同物理实体使用同一套基本对象，但侧重不同：

| 实体 | 特别需要保存或选择的参数 |
| --- | --- |
| 地面基站/接入点 | 位置与高度、扇区/波束方向图、发射功率、频段、可分配资源、调度规则、回传接口上限 |
| 无人机 | 三维轨迹、速度与姿态、安装天线的指向、发射功率与频段、所用空地/空空信道模型 |
| 车辆或普通终端 | 轨迹与天线高度、车体或建筑遮挡、终端支持的频段/MCS/功率、接收机噪声系数 |
| 卫星 | 有时间基准的星历/轨道位置、波束及指向、载频与资源、网关位置、透明转发或星上再生方式；星间链路另定义介质 |

电量仅在它通过明确策略改变发射功率、接口状态或调度时进入模型。交换机 CPU/流表性能影响处理时延或吞吐瓶颈，应作为节点处理模型另列，不能写入无线传播损耗。

建议的最小配置对象为：`RadioProfile`（频段、可用频谱宽度、功率范围、天线模型、噪声系数、支持 MCS、设备速率上限及来源）、`NodeState(t)`（位置、速度、姿态、当前功率/频段/接口状态）、`EnvironmentState(t)`（障碍与天气、同频发射者、资源分配）及 `LinkModelProfile`（物理介质、制式、所选传播/速率模型及适用范围）。卫星额外关联星历和网关；没有选定无线制式时，`supported_mcs`、资源分配和速率映射不能凭节点名称推断。

对最终两个核心输出的影响可概括为：位置及物理路径变化会改变**传播时延和可用速率**；功率、天线、频率、接收机及遮挡主要改变**可用速率/可用性**，不会让电磁波因信号差而显著减速；频谱与调度资源直接限制**可用速率**；速率下降后实际业务可能产生更多**排队时延**，但排队时延不是仅由节点档案就能算出的固定链路属性。

## 3. 从物理输入到带宽和时延

对每条方向 `i → j`、每个仿真时刻 `t`，采用下列顺序：

1. **几何和可见性**：从位置计算传播路径长度 `d_ij(t)`、仰角、遮挡与天线方向。卫星场景使用地球曲率和对应星历，不能只拿“轨道高度”替代斜距。
2. **传播损耗**：按场景选定一个基础路径损耗模型，叠加该模型尚未包含的遮挡、阴影、天气等损耗。不可重复叠加已经包含在所选模型内的项。自由空间视距基线为 `PL_FS(dB) = 20 log10(4πdf/c)`；城市、车联网和卫星环境应换用各自适用的模型。
3. **接收功率与 SINR**：`P_rx(dBm) = P_tx + G_tx + G_rx - PL - L_other`。将目标信号、干扰和 `kTB × 噪声系数` 全部换为**线性功率**后计算 `SINR = S/(I+N)`；不可直接对 dBm 相加或相除。上、下行分别计算。
4. **速率**：以已选无线制式及设备支持范围，用 `SINR → MCS/BLER → 可分配资源上的净服务速率` 的曲线或测量表映射。标准中的 MCS/频谱效率表并不单独给出通用的 SINR 选择门限，仍需对应接收机、目标误块率及链路曲线或测量。没有对应曲线时，先采用明确标为“简化假设”的效率曲线，并做敏感性分析；`B log2(1+SINR)` 只能作理想化容量参考，不能直接当作仿真带宽。资源分配、控制开销、协议头和链路层重传的处理必须在速率标定中说明。输出 `bandwidth_mbps = min(设备/回传上限, 校准后的服务速率)`。
5. **传播时延**：无线单跳 `D_prop = d_ij/v`，自由空间基线取 `v≈c`。透明转发卫星的终端到网关路径是“终端→卫星→网关”两段传播时间之和；星上再生处理需另计。若一条逻辑链路代表多段物理路径，应记录所有段与处理边界。
6. **可用性与损失**：覆盖/仰角、接收门限、资源分配及设备状态共同决定是否可用。只有掌握重传策略、报文长度和经校准的误包曲线时，才推导重传后的残余包损失。`available=false` 是断链事件，不等于 `bandwidth=0` 的普通整形状态。

第一阶段采用确定性轨迹、遮挡事件和固定资源分配，生成可复现的时间线。第二阶段才增加有依据且具时间相关性的阴影/快衰落、干扰、调度和重传。更新间隔应由场景变化尺度与运行时可承受的下发频率共同决定，不承诺用逐包 `tc` 更新复现 PHY 快衰落。

## 4. 时延口径及 Mininet 映射

物理链路的单包传播、序列化和其他等待必须分开：

```text
理论/协议分解：D_end_to_end = Σ(D_prop + D_serial + D_access
                            + D_retx + D_queue + D_proc)
```

`D_serial = L_bits / R_phy` 描述在物理发送速率 `R_phy` 下把指定报文串行送上介质的时间。若 `bandwidth_mbps` 是经过调度、头部开销和重传标定的**网络层服务速率**，`L/bandwidth` 只是服务时间近似，不能再称为精确 PHY 序列化时延。

在 Mininet 中，`tc` 的 TBF/HTB 用来约束出口速率，内核队列随真实业务负载产生等待；`netem` 用来施加可实现的**附加**延迟和经定义的残余损失。TBF 是令牌桶，允许突发，缺令牌才排队，因此设置 `20 Mb/s` 并不保证每个 1500 Byte 包都恰好增加 `0.6 ms`。不能同时根据 `L/R` 再加一个固定 `netem delay`，也不能先算一个固定排队时延再叠加真实队列。[Linux TBF](https://www.man7.org/linux/man-pages/man8/tc-tbf.8.html)、[Linux netem](https://www.man7.org/linux/man-pages/man8/tc-netem.8.html)、[Mininet TCIntf](https://mininet.org/api/classmininet_1_1link_1_1TCIntf.html)说明了这些机制及计时限制。

`ChannelState.delay_ms` 是模型中的目标传播时延，并非能原样传给 `netem` 的数值。下发前需按链路类型、报文长度及低负载条件测量虚拟链路/物理 underlay 基线，再确定非负附加延迟及精度容差；若基线高于目标或目标低于系统计时分辨率，记录“不可精确实现”，不能声称复现。对卫星的毫秒级传播延迟，这种网络层映射通常更有用；对近距离车联网的微秒级传播延迟，重点通常是容量、接入、排队和残余损失。

接入等待、链路层重传和处理时延若以后需要模拟，应增设**有独立来源**的附加模型，并检查它们是否已隐含在目标速率、损失或实测基线中。无模型时标记未建模，不能把信号恶化直接写成一个任意增加的 `delay_ms`。

## 5. 按场景选择模型

| 研究场景 | 基线选择 | 必须核对的范围与缺口 |
| --- | --- | --- |
| 一般视距无线/空空链路 | 自由空间路径损耗与几何传播时间 | 天线方向、遮挡、共享频谱、资源分配与适用远场范围 |
| 地面蜂窝基站与终端 | [3GPP TR 38.901](https://www.etsi.org/deliver/etsi_tr/138900_138999/138901/19.03.00_60/tr_138901v190300p.pdf) 中匹配的城市/农村场景 | 频率、天线高度、距离范围及 LOS/NLOS 条件；还需要所选制式的链路适配与调度 |
| 车辆直连 | [3GPP TR 37.885](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3209) 的城市/高速与 LOS、车辆遮挡、建筑遮挡分类 | 轨迹、建筑/车辆遮挡、频谱共享、V2X 技术类型；[ns-3 实现说明](https://www.nsnam.org/docs/models/html/propagation.html#models-for-vehicular-environments)可作为核对入口 |
| 无人机与地面 | 先做视距几何基线，再按频段/业务选择 [3GPP TR 36.777](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3231) 或适用的 [ITU-R P.528](https://www.itu.int/rec/R-REC-P.528-5-202109-I) | 高度、地形/建筑、仰角、天线姿态和空地干扰；不能把所有空地链路都套入一个通用指数 |
| 卫星与地面 | [3GPP TR 38.811](https://atisorg.s3.amazonaws.com/archive/3gpp-documents/Rel15/ATIS.3GPP.38.811.V1530.pdf) 的轨道/仰角、损耗与延迟；适用时加 [ITU-R P.618](https://www.itu.int/rec/R-REC-P.618-14-202308-I) 雨衰 | 用户链路、馈线、透明转发/星上再生分别建模；P.618 的长期统计不能直接冒充逐秒天气轨迹 |

## 6. 与当前源码的接入顺序

1. 保留 `Scene` 的拓扑身份与当前 `channel-plan` 的通用静态配置。另定义物理设备档案、节点时间状态、共享环境与无线模型配置，均绑定 `scene_digest`；不要将无线字段强加到有线端口。
2. 实现纯计算 `state_at(sim_time_ms)`，输出每条候选链路的双向状态及中间诊断量：路径长度、LOS、路径损耗、接收功率、SINR、选定 MCS/资源及模型版本。诊断量用于追溯，不直接写入 `tc`。
3. 对同一全局时间线和随机种子预计算状态；Worker 只接收负责出口的版本化更新。跨 Worker VXLAN 的可整形位置必须单独确认，不能假设 OVS 隧道端口可直接挂 `tc`。
4. 将断链事件交给转发面和路由策略。当前 `Scene` 只支持已声明连边、主机恰好一条业务链路且不支持主机直连；真正的车辆邻居发现、基站切换或新建卫星链路，需要先扩展候选拓扑和控制器的静态路径逻辑。
5. 后续验证分别记录模型目标、内核配置、实际吞吐、单向报文时延、队列、损失及状态生效误差，不能用 RTT 代替两个方向的单向传播时延。

本设计的关键前提是**先确定要模拟的无线技术与场景**。只有“节点是卫星/无人机/基站”仍不能唯一确定 MCS、共享资源、链路层重传和由此得到的数值速率；在选定技术或取得测量曲线前，速率应明确标为场景假设。
